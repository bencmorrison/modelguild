# Testing

Every test suite, lint and local proof in the repository, and what each one asserts. The commands to run and when are the **Commands** table in [AGENTS.md](../AGENTS.md); the conventions for writing tests are the path-scoped rule `.claude/rules/testing.md`, which Claude Code loads when it touches the test tree and opencode loads through `opencode.json`.

- **`npx modelguild doctor`** — token-free health check (`src/cli.ts`): the MCP server registered under key `modelguild` (checked in **any scope** via `claude mcp get modelguild` when the `claude` CLI is on PATH, since a global `-s user` registration lives in `~/.claude.json`, not the project `.mcp.json`; falls back to the project file, and downgrades a project-file miss to a **warning** when `claude` is absent so a working global setup is never reported as broken), the command docs and hardened agent defs present, the model policy present (**default mode counts each as present if found in the project OR the global location** — `.claude/commands/guild/` or `~/.claude/commands/guild/`, `.opencode/agent/` or the global opencode agent dir, `modelguild/models.policy` or `~/.claude/modelguild/models.policy` — mirroring how each resolves at runtime, so a global-only install passes plain `doctor`; `--global` checks the global locations alone; fail-closed when found in neither), **payload skew and upgrade drift** (issues #94/#22 — installed files behind what this release ships: *skew* = ours and untouched (fixed in place by `npx modelguild init`), *drift* = ours and user-edited (reported, never overwritten), plus an honest "cannot judge without an ownership record" for unrecorded differences; **all three are warnings that never change the exit code**, and `GUILD_PAYLOAD_NOTICE=off` does **not** silence them here — it governs the server's start-up line alone), **opencode on PATH — a HARD FAILURE since issue #151 — and opencode AUTH, a WARNING**, plus, on every failing line, a NEGATIVE form rather than a positive sentence under a `✗`. The severity was inverted: a missing binary — the one condition guaranteeing no model can ever answer — was a `!` under `doctor: OK` while an unregistered MCP server was a `✗`; it is now `✗`/exit 1, `--version` failing on a binary that IS on PATH is a distinct message naming the exit status, and a spawn error is classified by **errno** (only `ENOENT` says "not found on PATH"; `EACCES` and friends say *could not execute*, because telling that user to install opencode points at the wrong problem). **The auth check is `opencode auth list`** (`opencodeAuthState` in `src/cli.ts`), skipped whenever the **binary check failed** — missing or on-PATH-but-broken alike — so one cause is never reported twice. **The exit code carries nothing — it is 0 in every state (probed, 1.18.11)** — so the counts are the signal, read as **line-final footers with the last match winning** (an unanchored search took an embedded `0 credentials-migrated` or an earlier stray count as the answer), and **BOTH credential sources are summed**: stored credentials *and* provider API-key environment variables, which `auth list` reports in a second `Environment` section printed only when non-empty. Unparseable output or a failed run ⇒ a **`!` "could not determine"** — fail-open, because nothing-learned must never be reported as unauthenticated. **Zero of both is a `!` WARNING, not a `✗` — maintainer decision 2026-08-03, after two independent reviews reached it, and the reason is that the probe has BLIND SPOTS, plural:** a provider declared straight into `opencode.json` is invisible to `auth list` in at least two probed shapes — an `apiKey` in the provider options, and a local or OpenAI-compatible endpoint needing **no credential at all** — both printing "0 credentials" while models answer. A zero is therefore evidence, not proof, and the warning names both shapes as a possible false alarm. **That is this file's existing posture, which is the whole argument:** the MCP-registration check already downgrades to a warning when `claude` is absent rather than call a working global setup broken, and C72 keeps skew/drift report-only. The binary checks stay hard because they have no such blind spot. **C72's "skew and drift never change the exit code" is untouched** — that rule is about the installed PAYLOAD's state (behind a release is not broken), this is about the binary the system runs on. Contract clause **C75**; covered by `test/doctor.test.ts` cases (s)–(z), which shadow PATH with a fake `opencode` (the `test/serve-stderr.test.ts` injection point) so the verdict is a pure function of the payload plus the two opencode checks. It also prints the **layered config/policy chain** (issue #19) — every root layer most-specific first, then every policy file in the chain with a presence marker, ending at `default-allow` — so what actually binds is visible, not just the winner. It reads the real `process.env` for that line so a `$GUILD_ROOT`/`$GUILD_POLICY` override is reflected honestly. No model is called. The `guild_status` MCP tool adds the live checks (serve up, plus the doctor-seed: primary root, the ordered root layers, the policy layer chain with presence, the `$GUILD_ROOT`-unlayered note, logging, the approval bridge, and — since issue #94 — the payload classification as `structuredContent.payload`, carrying the deciding installed-vs-shipped hashes). It still does **not** call `runDoctor`: the two share the *detection* (`scanInstalledPayload`), not the report, so the paste-able `diff` hints and the MCP-registration/PATH checks stay `doctor`-only.
- **`npx modelguild logs clean [--days N] [--dry-run] [--dir D]`** — token-free evidence-log maintenance (issue #23), `runLogsClean` in `src/cli.ts`. `--dry-run` is the safe way to see what retention would take. Refuses (exit 2) rather than guessing when no usable window is configured. Covered by `test/log.test.ts` (sections 14a–14h), which also spawns a real `src/server.ts` to prove the start-up prune is actually wired — that spawn needs no opencode, since the prune happens before `connect` and the process exits on the stdin EOF the test hands it.
- **`npm test`** (`test/run.ts`) — the TS test suite, the reference for the behavioral spec (CONTRACT.md). It runs every `test/*.test.ts` suite — or, since issue #194, only the suite(s) named on the command line (`npx tsx test/run.ts <name>…`), with an unknown name refused up front rather than silently running everything; no model is called and spawning `opencode serve` is free. The **offline** ones (client, activity, approve, log, policy, config, consult, panel, research, delegate, models, init, doctor) are driven by an in-process `node:http` fake (`test/fake-opencode-server.ts`), real git, and `jq` — plus **serve-stderr**, offline by a different route: a fake `opencode` script placed first on **PATH**, so it drives the real `spawn("opencode", …)` rather than a test-only command knob production would never take; three (lifecycle, orphan, mcp-client) spawn the real `opencode serve` to prove process lifecycle and have **no graceful skip** if the binary is absent. **Suite counts are deliberately not stated here** — `test/run.ts` and the CI name list are the source of truth, and a number in prose drifts the moment a suite is added (it had, twice, before this line was written). `test/*.live.ts` are opt-in live smokes (`npm run test:live`, free models). The evidence-layer tests pin the `expected-call` → `started` → `completed` lifecycle, shared `call_id`, both-direction cardinality, byte-exact responses, and hash integrity — plus (issue #80) the multi-session races on ONE logs root, driven by real child processes because synchronous fs calls inside a single process can never interleave. The **activity** suite is offline for the same reason the rest are: the fake serves a SCRIPTED `text/event-stream` on `GET /event`, so the normalizer is asserted against the raw `{type, properties}` shapes the Slice 0 probe actually observed, not against a convenience shape of our own invention. The **approve** suite is offline for a stronger reason than convenience: its fake `POST /session` STORES and ECHOES the ruleset, and a gated turn **blocks** until a reply lands — reproducing the two `opencode serve` behaviours probe P2/P3 found — so "the ruleset took" and "the tool actually waited for the answer" are asserted, not assumed. It also serves `GET /permission` from that same open-request map and can raise a gated request **while every event client is detached** (issue #91), so the re-list is proved by a turn that can only complete if the recovery works — not by a timing race the test happens to win. **`doctor`'s old environment dependency is GONE as of issue #151, and the reason it had to go is the shape to keep in mind.** It used to run under the ambient PATH, so the verdict depended on two host facts: whether the `claude` CLI was present (present-and-answering-"not registered" is a hard fail, so absolute `exit 0` assertions went red on a dev box and green in CI), and — once a missing `opencode` became a hard fail too — whether opencode was installed, which CI deliberately does not do. `test/doctor.test.ts` now **shadows PATH for its whole run** with a stub `opencode` reporting itself present and authenticated, and no `claude`; cases (s)–(z) nest their own PATH inside that to vary the opencode state. So it is green in CI and on a dev box alike and a local red is a real red. The **baseline-relative** pattern is kept anyway in the issue-#22/#94 drift and skew cases — comparing against a `base` doctor run rather than a literal 0 is the honest assertion, since what those cases claim is that drift does not *change* the verdict.
- **`test/worktree.test.ts`** (part of `npm test`, and named in CI's node list) — the issue-#96 read root, offline. It drives **real git** (`git init`, `git worktree add`) because the whole fence is a `git worktree list` membership test, so a faked git would be faking the thing under test. It pins: a sibling worktree accepted; the main checkout accepted and flagged as the default root (no second child); an off-list path, a worktree of a **different** repository, a nonexistent path, a non-repo project dir and a failing git each REFUSED with the path named; a refusal routing nothing and writing **no** evidence run (gap parity); the serve child actually rooted at the target (a `ServeRouter` spy records the root it was asked for); a worktree with no hardened def refusing as `agent-def-missing` **naming that worktree's own `.opencode/agent`** — the silent-break guard, since opencode resolves agents from the serve's cwd; and the pool's per-root reuse plus its teardown through `OpencodeLifecycle.onShutdown`. **The WRITE root (issue #107) is pinned next door, in `test/delegate.test.ts` section H**, because it needs that file's real-git mutation harness: it asserts the model's edits land in the target tree, that **the recorded patch is of the target tree** (with a sentinel file written into the *other* tree, and an inversion case where the mutation happens in the project root while the call targets the worktree — both fail the moment the capture root and the edit root diverge), that the recovery hint names the target, the two refusals, the up-front def refusal with nothing logged, that the approval bridge's allow-set comes from the def in the target tree, and that an untargeted call is unchanged down to the entry shape. **Section I (issue #108) is the scaffold-out-of-the-staging proof**, and it is behavioural for the same reason: a fixture repo that **commits** its own `.opencode/.gitignore` (so nothing ignores what opencode writes), the scaffolding created *between* the two snapshots, and the patch asserted to carry the model's real edit and the `.opencode/agent` def change while carrying none of `node_modules`/the manifests — plus the tracked-manifest inversion (a committed `.opencode/package.json` the model edits **does** appear), `scaffoldChanged` still firing in both, and the scaffolding-only turn that now reports "nothing to review". It failed on six assertions against the pre-fix code.
- **`test/agentfloor.test.ts`** (part of `npm test`, and named in CI's node list) — the issue-#111 resolved-agent check, offline. The fake serves `GET /agent`, and a case fixtures a **RESOLUTION** rather than a def file (`hardenedAgent()` / `voidedAgent()` in `test/fake-opencode-server.ts`, whose voided shape is the probed one: opencode's built-ins alone, `description: null`, `mode: "all"`) — because what the source says is precisely what this feature proves is not the question. It pins: the effective-action semantics, including the case a presence test would pass (a floor followed by a later `"*": allow`) and the one a pattern-blind test would fail (a `"*"` rule with a narrow pattern is not a floor); an unreadable rule entry failing the WHOLE array rather than being dropped; the refusal on all four tools, naming the agent and what was resolved, with **no** model call, **no** session, and **no** evidence run — and on `guild_delegate`, no capture and nothing written into the repo; the panel's ONE check for three members (asserted on a `GET /agent` request counter, not on timing); the per-child cache proving no leak in either direction between two roots; the cannot-ask direction proceeding **and** surfacing on both channels; and the ordering assertion — a voided def plus a bad `GUILD_APPROVE` value must produce the FLOOR refusal, because the bridge may never arm against a def that is not in force. One case exists to keep every OTHER suite honest: it asserts the fake's default `/agent` payload really is hardened, so their silence means "verified", not "never asked". **`mutatingServe` in `test/delegate.test.ts` moved from `withServe` to the message POST for this change** — a tool may now enter `withServe` more than once per call, and a fixture that mutated per entry applied the "model's" edits before the baseline snapshot; the fixture was wrong about when a model edits files, and the tempting alternative (moving the product's check after the snapshot) is what C73 forbids.
- **`bash modelguild/tests/check-shebangs.sh [file...] [--self-test]`** — asserts every tracked file that declares an interpreter starts with exactly `#!/usr/bin/env bash`. Opencode-free; runs in CI. `--self-test` proves it catches `#!/bin/bash`, `#!/bin/sh`, trailing-flag variants and extension-less scripts, and ignores non-scripts (ported from the retired `run-tests.sh` meta-tests).
- **`bash modelguild/tests/check-frontmatter.sh [--self-test]`** — structural lint of the YAML frontmatter in `.claude/commands/*.md` (needs `description`) and `.opencode/agent/*.md` (needs `description`/`mode`/`permission`): asserts the `---` fences and required keys. `--self-test` proves it rejects a missing opening fence, a missing closing fence and each required key dropped on its own, in a command doc and an agent def alike, and **accepts** the real files — asserting on the failure *reason*, so a lint that fails for the wrong reason is caught rather than counted as a pass. **It SHORT-CIRCUITS, like `check-agent-permissions.sh`'s: `--self-test` does not also scan the repo, so CI must invoke the script TWICE** — plain, then `--self-test`. Running only the second is the mistake to avoid; it leaves the real command docs and agent defs unlinted while looking like the stricter invocation. That gap was real until issue #166: the flag was accepted and silently ignored, and CI ran this lint plain while running every sibling's `--self-test`, so the green proved the lint ran and never that it still bites. Runs in CI (shell + macOS).
- **`bash modelguild/tests/check-docs.sh [--self-test]`** — token-free lint for obsolete unnamespaced command names, broad `log.sh:*` grants, that every command doc drives the MCP tools and touches **zero** collab bash (no `ask.sh`/`log.sh`/`panel-models.sh`, no `Bash(opencode …)`), and stale two-entry lifecycle claims. Runs in CI (its `--self-test` runs the lint then proves it rejects each regression).
- **`bash modelguild/tests/check-contract-counts.sh [--self-test]`** — token-free **structural** lint of CONTRACT.md; it keeps its counts-era name but now asserts two things, neither of which reads the prose meaning. (1) **Counts** (issue #36): the command/agent-def counts CONTRACT.md states in prose match the source of truth in `src/init.ts` (`COMMAND_DOCS`/`AGENT_DEFS`), via three anchored statements — "<word> namespaced commands" (C41), "(<n> files" (F oracle), "<word> hardened agent defs" (C47) — so a retirement that bumps a code count but leaves CONTRACT.md stale fails CI. (2) **Clause-id uniqueness** (issue #113): every `- **C<n>**` id appears exactly once. Clause numbers are cited as identifiers from `AGENTS.md`, `src/` comments and commit messages, so a number resolving to two clauses makes every citation of it ambiguous in both directions — and prose has no typechecker, which is how two same-day merges (PRs #109 and #110) each added a **C71** without conflicting textually. **The letter suffix is PART of the id:** `C32` and `C32a` are distinct ids and both are allowed; stripping the suffix is exactly what makes a naive grep report that pair as a duplicate. `--self-test` mutates each count in a fixture, and — asserting on the failure *reason*, not just the exit code — proves the lint bites on a duplicated id (suffixed or not) and on a removed anchor, while **accepting** a `Cnn`/`Cnna` pair. Runs in CI.
- **`bash modelguild/tests/check-agent-permissions.sh [--self-test]`** — **opencode-free** source-level lint of the three hardened agent defs' permission maps: frontmatter opencode can parse (no duplicate key at any depth, no tab indentation), `mode: all`, a `"*": deny` floor, **no** `"*": allow`, and the allow-set is exactly the agent's intended tools (`guild-read`/`guild-research` = read+grep+glob+web; `guild-build` = edit/write/patch/bash). **`read` is checked the same way on all three** — a plain top-level `read: allow` with **no** submap — since `guild-build` dropped its secret globs (2026-07-29, issue #29); the per-agent read-shape parameter went with them. It does not prove opencode's resolved enforcement (that's `verify-guild-*.sh`) — it guards the realistic regression: a human editing an agent `.md` and weakening it. `--self-test` proves it catches write re-added to a read path, a missing floor, a floor placed after the allows, a `"*": allow` overriding the floor, an unintended tool added to the allow-set, a **re-added** secret-glob read submap — that case is the old "a dropped secret glob" test **inverted**: re-fencing a read tool `bash` can walk around is now the regression, not the fix — and the issue-#100 set: a duplicated `mode:` key in **either** order, a duplicated `permission:` key, a duplicate **nested inside** the permission map, tab indentation, and — the false-positive direction — that the same key name in **two different mappings** (`"*"` in the permission map and again in a `read:` submap, a def opencode parses fine) is **not** reported as a duplicate, asserted on the failure *reason* rather than the exit code. **The duplicate is rejected outright rather than resolved by last-match**, which is the point: a last-match rule would have to assert which value opencode's parser honours, and asserting that from assumption is how the hole got here — `mode: all` was checked by PRESENCE, so `mode: all` followed by `mode: subagent` passed. The probe found the duplicate is not merely ambiguous, it voids the whole map; the lint does not need to know that to refuse the def. Detection is scope-aware (a key namespace per mapping, scope ids that only increase, so the stack unwinds without deleting popped entries — a bash 3.2 / BSD awk trap). Runs in CI.
- **`bash modelguild/tests/check-claude-md.sh [--self-test]`** — **opencode-free** structural check of the `CLAUDE.md` thin-pointer invariant (issue #28, regaining the machine check the retired bash `doctor.sh` had): `CLAUDE.md` is a regular file (not a symlink), its first non-empty line is exactly `@AGENTS.md`, it stays under the 60-line anti-fork ceiling, and it contains none of a small set of distinctive literal markers of `AGENTS.md`'s shared rules (chosen to distinguish restatement from the pointer sentences that legitimately *name* those concepts). **Each marker is also asserted to still MATCH `AGENTS.md` (issue #123)**, case-insensitively — reword a rule here and its tripwire would otherwise grep for a string that exists nowhere, CI green. **Never quote a marker verbatim in this file:** the second copy keeps the tripwire matching after the rule itself is reworded. It does **not** catch a shared rule paraphrased in novel words — that semantic discipline stays human judgment. `--self-test` proves it rejects a missing `@AGENTS.md` first line, an over-ceiling file, a restated shared rule, a marker **reworded away in `AGENTS.md`**, and a symlinked `CLAUDE.md`, and accepts the real current file. Runs in CI (shell + macOS).
- **`bash modelguild/tests/check-agents-size.sh [--self-test]`** — holds the always-loaded instruction files (`AGENTS.md`, `CLAUDE.md`, every `.claude/rules/*.md`) under 40,000 bytes, the floor of Claude Code's per-memory-file warning (`max(40000, round(contextWindow × 0.05 × charsPerToken))`, read from the 2.1.259 bundle; 150,000 on a 1M-context model). A harness limit, not the words-per-item lint retired on issue #122. `--self-test` proves it rejects an over-limit `AGENTS.md` and an over-limit rule file and accepts the current ones. Runs in CI (shell + macOS).
- **`bash modelguild/tests/check-v1-permission-pin.sh [--self-test]`** — **opencode-free** guard on the issue #93 / CONTRACT C69a decision: no **non-comment** line in `src/**/*.ts` may construct a **literal v2 PERMISSION path** (`/api/permission…`, `/api/session/<id>/permission…`), the V1 PIN record must still be in `src/client.ts`, every src file that constructs a v1 permission reply must still point at it (the file list is **discovered, not hard-coded**, so the check follows the code if `replyToPermission` moves), and `verify-permission-surface.sh` must still exist so "re-probe first" stays actionable. **Scoped to the permission surface on purpose:** 1.18.7 exposes ~51 `/api/` paths and ModelGuild speaks the v1 counterparts of several, so a blanket `/api/` ban would fail an unrelated migration (`guild_models` → `GET /api/model`) with a message about the approval bridge — and get deleted. Comments are stripped by a **state machine**, not a leading-token heuristic — inline `/* … */`, block-comment body lines with no leading `*`, and trailing `// …` (never a `://`) — plus a path-boundary rule so a `docs/api/permission` URL does not trip it; "inspects non-comment lines" has to be true rather than nearly true. It is a **literal** grep: a split or computed prefix evades it by construction, and the self-test asserts those escapes as **accepted**, so the documented limit is executable rather than aspirational. `--self-test` proves both directions, including that `/api/model`, `/api/event` and `/api/session/{id}/message` are accepted, that deleting or **moving** the record is caught (the record is located by content, not filename), and that moving it to another src file still passes. Runs in CI (shell + macOS; BSD grep is the portability risk).
- **`bash modelguild/tests/check-shellcheck.sh [file...] [--self-test]`** — runs ShellCheck (`--severity=warning`) over every tracked shell script; skips cleanly when shellcheck is absent. Single source of truth (CI calls this script). `--self-test` proves the skip path plus (when shellcheck is present) accept/catch of an SC2046 finding.
- **CI (`.github/workflows/ci.yml`)** — three jobs, all credential-free and opencode-free (no opencode session in CI, ever):
  - **`shell`** (Linux): `bash -n`, ShellCheck, and the surviving lints (shebangs, frontmatter, docs, contract-counts, claude-md, agents-size, v1-permission-pin, agent-permissions, host-config confinement, host-timezone detection), each also run against its own `--self-test` (which replaced the retired `run-tests.sh` meta-tests as the proof the lints still catch regressions).
  - **`macos`** (stock bash 3.2 + BSD awk/sed/grep): the same lints, on the platform difference no lint can catch. It shadows `bash` on PATH with `/bin/bash` and hard-fails if that is not 3.x. Two bug classes it exists for: `set -u` + empty array aborting on bash 3.2 (use `${arr[@]+"${arr[@]}"}`), and BSD `mktemp` ignoring `TMPDIR`. It does NOT brew-install ShellCheck (identical results on either OS). `coreutils`/`gtimeout` is no longer installed — the delegate fixtures that needed it retired with the bash test harness.
  - **`node`**: `npx tsc --noEmit` + the offline test suites via `npm run test:offline` — `test/run.ts --offline`, the ONE canonical opencode-free selection since issue #166, which prints the suites it excludes so a green run always means the rest executed, never a skipped-everything pass; the opencode-needing suites are named as excluded in `test/run.ts`'s `OFFLINE_EXCLUDED`, not in the workflow. `doctor` was **missing** from that list until issue #22 — it ran only under a local `npm test`, so its coverage was never CI-enforced; it is offline and now included.
- **`bash modelguild/verify-guild-read.sh` / `verify-guild-build.sh` / `verify-guild-research.sh` `[--static]`** — the authoritative proofs that opencode's **resolved** permission config matches each agent's intended allowlist. They call `opencode` directly (no dependency on any retired bash), so they need a logged-in opencode and run **locally** after an opencode/agent-def bump — never in CI (credential-free). `--static` runs only the token-free resolved-config check + a known-key lint; without it, a runtime probe (write-attempt / edit-path) corroborates on a free model, reported INCONCLUSIVE (not PASS) if opencode can't run. `verify-guild-read`/`research` assert `"*": deny`, `read`/`grep`/`glob`/`webfetch`/`websearch` allowed, mutation/`task` denied, and **no** former secret-glob read-deny remains; `verify-guild-build` asserts edit/write/patch/bash **and `read`** allowed, everything else (`task`/`grep`/`glob`/`webfetch`/`websearch`) denied, and — since 2026-07-29 (issue #29) — that **no** secret-glob read-deny remains there either. That last assertion replaced the one that required them; it is the same check the read paths already carried, and it is a fence coming off, not a guarantee being added.
- **`bash modelguild/verify-permission-surface.sh`** — same family, same workflow slot (local only, after an opencode bump; never CI), different question: it makes issue #93's "re-probe before migrating" **executable**. It spawns a serve (or uses `$GUILD_VERIFY_BASE_URL`) and, for each agent in `$GUILD_VERIFY_MATRIX` (default: the armable tiers — `guild-build:bash|edit|patch`, `guild-read:webfetch|websearch`), creates a gated session carrying `{permission,*,ask}` rules and a control session carrying none, then evaluates each permission on `POST /api/session/{id}/permission` `$GUILD_VERIFY_ROUNDS` times per session and judges whether the ruleset **changed** the answer. **Differential by necessity** — an `ask` from v2 can come from the agent def or a built-in rule — and it **refuses to conclude** in four shapes, each of which was a real route to a false green: the stored ruleset not structurally intact (a substring check passes a ruleset that *denies* bash and asks about `read`), a control that shows the agent never allowed the tool, both creates returning one session id (no control at all), and rounds that disagree within **either** session (an unstable sample is not a verdict — #93 records a real first-call instability). Covering all armable families is deliberate: a verdict from `bash` alone would generalize past its evidence, so the PIN-HOLDS banner names the pairs it actually evaluated. Exit 0 = pin holds (the expected result on 1.18.7, reported as a result rather than a failure), exit 7 = **ATTENTION, revisit #93**, exit 6 = INCONCLUSIVE, deliberately distinct so "could not check" never reads as "pin holds". It calls **no model**, so unlike the `verify-guild-*.sh` runtime probes it does not need a logged-in opencode. There is no `--static` mode — every question it asks is about the running serve.
